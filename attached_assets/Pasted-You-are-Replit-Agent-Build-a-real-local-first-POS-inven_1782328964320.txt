7. Autosave / Crash-Safe Drafts
===============================

This is a core requirement.

The shop may lose electricity while the cashier is filling a long invoice, quotation, purchase invoice, stock count, product form, customer form, or supplier form.

The system must not depend only on a final Save button.

Implement autosave and crash-safe drafts.

Requirements:

* Autosave form data while the user is typing.
* Use debounced autosave, for example every 1–2 seconds after changes.
* Save drafts in the local SQLite database, not only in browser memory.
* Show a visible state:

  * Saving...
  * Saved automatically
  * Unsaved changes
* If the app closes, browser crashes, or electricity cuts off, restore the last unfinished draft when the user opens the same page again.
* Show a recovery message:
  “تم العثور على مسودة غير مكتملة. هل تريد استكمالها أم حذفها؟”
* Drafts must be separate from finalized records.
* Drafts must not affect inventory quantities.
* Drafts must not affect customer debt.
* Drafts must not affect supplier debt.
* Drafts must not affect cash balance.
* Inventory, debt, and cash must only change when the user finalizes/submits the invoice.
* Final submission must run inside a database transaction.
* Allow user to discard a draft manually.
* Store draft timestamps and user/cashier name when available.

Important examples:

* A quotation draft can autosave, but it must not reduce stock.
* A sales invoice draft can autosave, but it must not reduce stock until finalized.
* A purchase invoice draft can autosave, but it must not increase stock until finalized.
* A stock count draft can autosave, but it must not adjust stock until reconciliation is confirmed.

19. Accurate Pricing and Percentage System
==========================================

This is critical for accounting accuracy.

In this Egyptian market, the word “percentage / النسبة” can mean different things. The system must not confuse them.

Support these different percentage types:

1. Supplier trade discount from list price
2. Customer discount
3. Profit margin
4. Markup on cost
5. Craftsman commission
6. Sequential discounts
7. Optional tax/withholding fields if needed later

Important concepts:

Supplier trade discount:
This is a discount from the company/list price, not the shop’s profit.

Example:
List price = 1000
Supplier discount = 30%
Net purchase price = 700

But if sold for 900:
Profit = 900 - 700 = 200
Profit margin = 200 / 900 = 22.22%
Markup = 200 / 700 = 28.57%

So supplier discount is not equal to profit.

Sequential discount:

If discount is 20% + 10%, do not calculate as 30%.

Correct calculation:
1000 -> 20% discount = 800
800 -> 10% discount = 720
Effective discount = 28%

Support sequential discounts as optional text/input like:
20+10
or separate discount fields.

Product pricing fields:

* List price
* Supplier discount percentage
* Supplier sequential discount optional
* Net purchase price
* Extra cost
* True cost
* Suggested selling price
* Customer discount
* Craftsman commission
* Profit value
* Profit margin
* Markup

Formula examples:

Net purchase price = List price × (1 - Supplier discount)

True cost = Net purchase price + extra costs

Profit = Selling price - True cost - craftsman commission

Profit margin = Profit / Selling price

Markup = Profit / True cost

When creating invoices, show warning if selling price is below true cost or below minimum price.

Never treat supplier discount as profit.
