# AGENTS.md — Local‑First POS (نظام المحل)

> Handoff guide for the next AI/dev agent. **Read this fully before editing.**
> Arabic‑first (RTL) **local‑first** POS & inventory system for an Egyptian
> sanitary‑ware / paints / plumbing shop. Target runtime: a **Windows** shop PC.
> Development: **macOS**. Database: **local SQLite**. No cloud, no paid hosting.

---

## 0. TL;DR — the 6 things that bite people

1. **Use Node 24.** The API server uses the built‑in `node:sqlite`, which only
   exists on Node ≥ 22.5. The machine's default `node` is **v20** → crashes with
   `No such built-in module: node:sqlite`. Run `nvm use 24` (there is an `.nvmrc`).
2. **The DB is SQLite via `node:sqlite`, NOT Postgres.** `lib/db` (Drizzle/PG) is
   unused template scaffolding. The real schema is `artifacts/api-server/src/lib/db.ts`.
3. **The backend is hand‑written; the frontend uses generated hooks from an
   OpenAPI spec.** If you change a route's shape, update `lib/api-spec/openapi.yaml`
   and re‑run codegen, or the POS typecheck breaks.
4. **The whole UI is RTL/Arabic.** Radix needs `<DirectionProvider dir="rtl">`
   (in `App.tsx`) — without it, tables inside `Tabs` render left‑to‑right.
5. **pnpm is strict (isolated node_modules).** A package can only import its
   *direct* deps. Add new libs to that package's `package.json` + `pnpm install`.
6. **Don't commit `data/store.db*`.** It holds local/seed/test data. Stage source
   files only.

## 1. How to run locally (verified working)

```bash
# one terminal — Node 24 required for node:sqlite
nvm use 24                 # or: export PATH="$HOME/.nvm/versions/node/v24.14.0/bin:$PATH"

# backend → http://localhost:8080  (health: /api/healthz)
PORT=8080 pnpm --filter @workspace/api-server run dev

# another terminal — frontend → http://localhost:24730
PORT=24730 BASE_PATH=/ pnpm --filter @workspace/pos run dev
```

- The Vite dev server **proxies `/api` → `http://localhost:8080`** (configured in
  `artifacts/pos/vite.config.ts`, *local only* — disabled when `REPL_ID` is set so
  Replit's own router is used). So the SPA and API share one origin in the browser.
- `PORT` **and** `BASE_PATH` are **required** by `vite.config.ts` (it throws if
  missing) — even for `pnpm --filter @workspace/pos run build`.
- `node:sqlite` prints an `ExperimentalWarning` — harmless.
- Build commands: `pnpm run typecheck` (all packages), `pnpm run build`,
  `pnpm --filter @workspace/api-spec run codegen` (regenerate client + zod).

## 3. The API contract (how the frontend talks to the backend)

- Frontend imports **hooks** from `@workspace/api-client-react` (e.g.
  `useListSalesInvoices`, `useGetCraftsman`). It also imports **imperative async
  functions** for event handlers (e.g. `searchProducts(...)`,
  `lookupSalesInvoiceBySerial(...)`).
- The backend is **hand‑written** and **not** generated from the spec. The spec is
  kept in sync **manually**.
- **Procedure when you change a route's request/response shape:**
  1. Edit the route in `artifacts/api-server/src/routes/*.ts`.
  2. Mirror the change in `lib/api-spec/openapi.yaml`.
  3. `pnpm --filter @workspace/api-spec run codegen` (regenerates client + zod, then typechecks libs).
  4. Update frontend usages; run `pnpm --filter @workspace/pos run typecheck`.
- **All list endpoints return `{ items, total }`** (every `*Page` schema). Reports
  use `dateFrom` / `dateTo` query params.

## 4. Database notes

- WAL mode. `initializeSchema()` runs on **every** startup using
  `CREATE TABLE/INDEX IF NOT EXISTS` → **idempotent**. To add a table/index, just
  add it there; it auto‑applies on next boot (existing columns are NOT altered —
  `IF NOT EXISTS` won't add a column to an existing table, so for new columns you
  must migrate explicitly).
- Serials come from `nextSerial(prefix)` using counters in the `settings` row.
- `data/store.db-shm` / `-wal` are **transient** — they show up as "modified" a lot.
  Don't commit them (ideally gitignore them; currently tracked).

## 5. Domain rules (don't break these)

- **Craftsman ↔ Customer linking:** a sales invoice / quotation may carry **both**
  an optional `customerId` and an optional `craftsmanId` (the introducer/worker).
- **Debt belongs to the CUSTOMER**, never the craftsman. `remainingAmount` is the
  customer's debt and feeds the debts page. Craftsman **commission**
  (`sales_invoices.craftsmanCommission`, % from `craftsmen.commissionPercent`) is
  tracked **separately**. **Never mix** customer debt / supplier debt / craftsman commission.
- **Quotation → invoice convert** preserves both ids, sets `invoice.quotationId`
  and `quotation.convertedInvoiceId`.
- **Pricing:** `netPurchase = listPrice × (1 − supplierDiscount%)`,
  `trueCost = net + extraCost`, `profit = sellingPrice − trueCost`.
- `/craftsmen/:id/customers` uses **correlated subqueries** (NOT a dual LEFT JOIN)
  to avoid aggregate fan‑out — keep it that way.

## 6. UI conventions

- **RTL + Arabic everywhere.** `index.html` = `<html lang="ar" dir="rtl">`, plus CSS
  `html, body { direction: rtl }`.
- **Radix needs RTL too:** the app is wrapped in `<DirectionProvider dir="rtl">`
  (`App.tsx`, from `@radix-ui/react-direction`). Removing it makes Radix `Tabs`
  emit `dir="ltr"`, which flips any `<table>` inside a tab to left‑to‑right.
- Money → `formatCurrency` (`src/lib/format.ts`). Animations → framer‑motion.
- Tailwind v4 + shadcn‑style components in `components/ui`.

## 8. Troubleshooting — likely problems & fixes

| Symptom | Cause / Fix |
|---|---|
| `No such built-in module: node:sqlite` | You're on Node 20. `nvm use 24`. |
| Backend `dev` builds then `start` crashes | The `start` step used a non‑24 Node. Ensure Node 24 is first on `PATH`. |
| `pnpm --filter @workspace/pos run typecheck` has errors | The OpenAPI spec lags the backend. Update `openapi.yaml` + run codegen. (libs + api‑server should be green.) |
| Tables inside a tab render left‑to‑right / headers not above data | `DirectionProvider` missing/removed, or a Radix wrapper without RTL. Check `App.tsx`. |
| Print shows the whole app / dialog frame / ✕ button | Check `@media print` in `index.css`: `#root{display:none}`, `[role=dialog]` reset, `.no-print` on overlay+close, invoice wrapped in `.invoice-print`. |
| Barcode doesn't render | jsbarcode draws into an `<svg>` ref inside `useEffect`; invalid values are caught silently. Verify the value is a valid Code128 string. |
| Scanner adds the wrong/no product | `/products/search?q=` matches `barcode` **exactly**; the product must have a `barcode`. `findProductByCode` prefers an exact barcode/SKU match. |
| Scanner triggers while typing by hand | Raise `minLength` or lower `maxGapMs` in `use-barcode-scanner.ts`. |
| Scanner fires when it shouldn't (closed dialog) | Use the hook's `enabled` option (quotations/purchases gate on `open`; POS gates on `!showFinalizeDialog && !showDraftDialog`). |
| Vite/esbuild won't start on macOS/Windows | Native binaries missing — make sure `pnpm-workspace.yaml` does **not** re‑add the platform‑exclude overrides, then `pnpm install`. (Old emergency workaround: set `ESBUILD_BINARY_PATH` to a fetched `@esbuild/darwin-arm64` binary.) |
| `pnpm install` adds an `allowBuilds:` block to `pnpm-workspace.yaml` | Harmless pnpm build‑script prompt noise — **revert it before committing**. |
| New import fails to resolve | pnpm strict mode — add the dep to that package's `package.json` and `pnpm install` (transitive deps are NOT importable). |
