# دليل التثبيت أول مرة على كمبيوتر المحل - Local First POS

> ده الدليل بتاع **المطوّر / المسؤول** اللي هيركّب النظام أول مرة على جهاز المحل (ويندوز).
> بعد ما تخلّص الخطوات دي مرة واحدة، **صاحب المحل** هيستخدم النظام بـ **دوبل كليك واحد**
> على اختصار اسمه **«نظام المحل»** — من غير ما يعرف حاجة عن Node ولا Git ولا pnpm ولا
> الأوامر ولا المنافذ.

---

## 1) فكرة النظام باختصار

- النظام **محلي بالكامل** — بيشتغل على نفس كمبيوتر المحل.
- بيفتح في **المتصفح** (Chrome أو Edge) على عنوان واحد: `http://localhost:8080`.
- **الداتا كلها على نفس الجهاز** (قاعدة بيانات SQLite محلية) — مافيش سحابة، مافيش إنترنت بعد التثبيت.
- بعد أول إعداد، **صاحب المحل بيستخدم الاختصار بس** — لا أوامر ولا نوافذ سوداء.

> ملاحظة تقنية: في وضع المحل، الخادم (Backend) هو اللي بيقدّم الواجهة (Frontend) من نفس
> المكان، فبيبقى عنوان واحد بس على المنفذ 8080.

---

## 2) البرامج المطلوبة أول مرة

| البرنامج | الإصدار | من فين |
|---|---|---|
| **Node.js** | **24** أو أحدث (مهم جدًا) | <https://nodejs.org> |
| **Git** | أي إصدار حديث | <https://git-scm.com/download/win> |
| **pnpm** | أحدث إصدار | بيتثبّت بأمر واحد (تحت) |
| **Google Chrome** أو **Microsoft Edge** | حديث | عادةً Edge متثبّت مع ويندوز |

> ⚠️ لازم **Node.js 24** بالظبط أو أحدث. النظام بيستخدم `node:sqlite` المدمج اللي مش
> موجود في الإصدارات الأقدم (زي 20). لو ظهرت رسالة `No such built-in module: node:sqlite`
> يبقى Node قديم.

---

## 3) خطوات التثبيت (بالأوامر)

> كل الأوامر دي في **Command Prompt** (ابحث عن `cmd` في قائمة ابدأ).

### 3.1 ثبّت Node.js 24
حمّله من <https://nodejs.org> وثبّته (Next → Next → Install). للتأكد:
```bat
node -v
```
لازم يطلع `v24.x` أو أحدث.

### 3.2 ثبّت Git
حمّله من <https://git-scm.com/download/win> وثبّته بالإعدادات الافتراضية. للتأكد:
```bat
git --version
```

### 3.3 ثبّت pnpm (لو مش موجود)
```bat
npm install -g pnpm
```
للتأكد:
```bat
pnpm -v
```

### 3.4 نزّل المشروع من GitHub
المكان المقترح للمشروع: `C:\POS`
```bat
cd C:\
git clone https://github.com/Usama1917/Local-First-Pos.git POS
cd POS
```

### 3.5 ثبّت الحزم (dependencies)
```bat
pnpm install
```
(أول مرة بتاخد دقائق — بتنزّل كل المكتبات. محتاج إنترنت في الخطوة دي بس.)

### 3.6 ابنِ النظام وتأكد إنه سليم (Build / Check)
```bat
pnpm run typecheck
pnpm --filter @workspace/pos run build
pnpm --filter @workspace/api-server run build
```
أو بأمر واحد مختصر بيبني الواجهة والخادم مع بعض:
```bat
pnpm run build:shop
```

> ✅ الطريقة الأسهل: بدل الخطوات 3.3 و3.5 و3.6 كلها، تقدر تشغّل ملف **`Setup POS.bat`**
> (دوبل كليك) وهو بيعمل كل ده لوحده (يفحص Node/Git/pnpm، يثبّت الحزم، ويبني النظام).

## 4) إنشاء اختصار «نظام المحل»

بعد ما تخلّص الإعداد، شغّل (دوبل كليك):
```
Create Desktop Shortcut.vbs
```
هيظهر على سطح المكتب اختصار اسمه **«نظام المحل»** — ده اللي صاحب المحل هيستخدمه يوميًا.

---

## 5) تشغيل الاختبار (للمطوّر — اختياري)

في وضع المحل النهائي، أمر واحد بيشغّل كل حاجة:
```bat
pnpm run start:shop
```
ده بيشغّل الخادم على المنفذ 8080، وهو بيقدّم الواجهة كمان. افتح المتصفح على:
```
http://localhost:8080
```
وللتأكد إن الخادم سليم:
```
http://localhost:8080/api/healthz
```
لازم يطلع `{"status":"ok"}`.

> هيظهر **تسجيل دخول**: المستخدم `admin` وكلمة المرور `admin123` (غيّرها بعدين).

### وضع التطوير اليدوي (نافذتين) — للاختبار فقط، مش لصاحب المحل
لو حبيت تختبر بنفس طريقة التطوير (الواجهة منفصلة عن الخادم):

**نافذة 1 — الخادم (API):**
```bat
cd C:\POS
set PORT=8080
pnpm --filter @workspace/api-server run dev
```

**نافذة 2 — الواجهة (Vite):**
```bat
cd C:\POS
set PORT=24730
set BASE_PATH=/
pnpm --filter @workspace/pos run dev
```
وافتح المتصفح على `http://localhost:24730`.

> ⚠️ طريقة النافذتين دي **للتطوير/الاختبار بس**. صاحب المحل **مايستخدمهاش** — هو بيشتغل
> بضغطة واحدة (وضع المحل على المنفذ 8080).

## 6) التشغيل اليومي لصاحب المحل

- **دوبل كليك على اختصار «نظام المحل»** على سطح المكتب.
- النظام بيشتغل لوحده، والمتصفح بيفتح على `http://localhost:8080`.
- **مايحتاجش يكتب أي أوامر** ولا يفتح أي نافذة سوداء.
- **مايقفلش الجهاز** والنظام شغّال وفي بيع.
- لو ظهرت **نافذة الخادم** (في وضع `Start POS.bat`)، **مايقفلهاش** — دي اللي بتشغّل النظام.
  (لو استخدم الاختصار العادي فالخادم بيشتغل صامت ومش بيظهر.)

ملفات التشغيل الجاهزة في المشروع:

| الملف | لمين | بيعمل إيه |
|---|---|---|
| **`Setup POS.bat`** | المطوّر (مرة واحدة) | يفحص المتطلبات + `pnpm install` + بناء أول مرة. |
| **`Create Desktop Shortcut.vbs`** | المطوّر (مرة واحدة) | يعمل اختصار «نظام المحل» على سطح المكتب. |
| **`Start POS.bat`** | يومي | يشغّل النظام على 8080 ويفتح المتصفح (بنافذة رسائل). |
| **`Start POS Hidden.vbs`** | يومي | نفس التشغيل بس صامت (ده اللي الاختصار بيستخدمه). |
| **`Stop POS.bat`** | عند الحاجة | يوقف الخادم. |
| **`Update POS.bat`** | المطوّر | نسخة احتياطية ثم `git pull` + `pnpm install` + بناء. |

## 7) مكان قاعدة البيانات

- افتراضيًا قاعدة البيانات في:
  ```
  C:\POS\data\store.db
  ```
- تقدر تغيّر المكان من داخل البرنامج: **الإعدادات → النسخ الاحتياطي → «مكان حفظ قاعدة
  البيانات»** → اكتب مسار (مثلًا `D:\POS-Data`) → احفظ → **أعد التشغيل**. (الأفضل تحطها
  برّه مجلد المشروع عشان التحديثات ما تلمسهاش.)

⚠️ **تحذيرات مهمة:**
- **ممنوع تمسح `store.db`** — دي فيها كل بيانات المحل (المنتجات، الفواتير، العملاء، الديون...).
- **ممنوع ترفع قاعدة بيانات المحل الحقيقية على GitHub** — ملفات الداتا متجاهلة تلقائيًا
  (مش بترفع)، خليها كده.
- **اعمل نسخة احتياطية قبل أي تحديث** (تحت).

---

## 8) التحديثات (لما يطلع تطوير جديد)

الفكرة: المطوّر بيطوّر على الماك، يرفع على GitHub، وعلى جهاز المحل بنجيب التحديث.

1. (مُستحسن) قفل النظام بـ **`Stop POS.bat`**.
2. دوبل كليك على **`Update POS.bat`** — بيعمل بالترتيب:
   - **نسخة احتياطية لقاعدة البيانات الأول** في
     `backups\store-backup-YYYY-MM-DD-HH-MM-SS.db`.
   - `git pull origin main`
   - `pnpm install`
   - `pnpm run build:shop`
3. بعد ما يخلّص، شغّل النظام عادي من الاختصار.

أو يدويًا في Command Prompt:
```bat
cd C:\POS
git pull origin main
pnpm install
pnpm run build:shop
```
> **اعمل نسخة احتياطية قبل أي تحديث.** التحديث **مش بيمسح ولا بيستبدل** قاعدة بياناتك،
> لكن النسخة الاحتياطية أمان إضافي.

### ملاحظات مهمة تخلّي التحديث بدون مشاكل
- **قاعدة البيانات بتترقّى لوحدها:** لو التحديث الجديد ضاف أعمدة/جداول (زي تسجيل «مين عمل
  الحركة»)، النظام بيضيفها **تلقائيًا أول ما يشتغل بعد التحديث** — من غير أي خطوة يدوية،
  وبدون ما يمس بياناتك القديمة.
- **لازم Node.js 24 أو أحدث** وقت التحديث (زي التثبيت). لو `node -v` طلع أقل من 24، حدّث Node
  الأول قبل `pnpm install`.
- **`pnpm install` بيكمّل لوحده** (مفيش أي سؤال عن build scripts محتاج رد) — سيبه لحد ما يخلّص.
- بعد `Update POS.bat` (أو `git pull` + `pnpm install` + `build:shop`) شغّل النظام عادي من
  الاختصار؛ التحديث اتطبّق بالكامل.
- **لو ظهرت أي رسالة خطأ** أثناء التحديث: النسخة الاحتياطية اتعملت الأول (في مجلد `backups`)،
  فبياناتك بأمان — كلّم المطوّر/المسؤول.

## 9) النسخ الاحتياطي

- من **الإعدادات → النسخ الاحتياطي → «إنشاء نسخة احتياطية»**: بيعمل **ملف مضغوط `.zip`**
  فيه قاعدة البيانات، والمتصفح **بيسألك تحفظه فين**.
- اعمل نسخة احتياطية **يوميًا**.
- **الأفضل تحفظها على فلاشة أو هارد خارجي** — مش على نفس الجهاز بس.
- **ما تعتمدش على نسخة واحدة** على نفس الكمبيوتر؛ لو الجهاز بظ تروح معاه.

## 10) حل المشاكل السريع

| المشكلة | الحل |
|---|---|
| إصدار Node غلط / `node:sqlite ... No such built-in module` | ثبّت **Node.js 24** أو أحدث، وتأكد بـ `node -v`. |
| `pnpm` مش متعرّف | ثبّته: `npm install -g pnpm` (أو شغّل `Setup POS.bat`). |
| `git` مش متعرّف | ثبّت Git من <https://git-scm.com/download/win>. |
| المتصفح مش بيفتح | افتح يدويًا `http://localhost:8080`. لو لسه، راجع `logs\pos-server.log`. |
| فحص الصحة بيفشل | افتح `http://localhost:8080/api/healthz`؛ لو مفيش رد شغّل `Start POS.bat` تاني. |
| المنفذ 8080 مشغول | شغّل `Stop POS.bat`، أو اقفل البرنامج اللي ماسك المنفذ. |
| قاعدة البيانات «ناقصة» | **ما تعملش setup من الأول**؛ دوّر على `data\store.db` أو استعد آخر نسخة احتياطية. |

## 11) ملاحظات مهمة (اقرأها كويس)

- **ما تمسحش مجلد `C:\POS`** — ده النظام كله.
- **ما تمسحش `data\store.db`** — دي بيانات المحل.
- **ما تشغّلش أوامر عشوائية** مش متأكد منها على جهاز المحل.
- **اسأل المطوّر/المسؤول قبل أي تحديث** أو تغيير كبير.
- **خليك دايمًا عندك نسخ احتياطية** على فلاشة/هارد خارجي.
- النظام **محلي** — ما يحتاجش إنترنت بعد التثبيت (الإنترنت بس وقت التثبيت والتحديث).
